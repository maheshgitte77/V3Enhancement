# V2.5 API Documentation

## Overview

V2.5 provides a completely independent multi-stage processing API for analyzing candidate responses. It's built on a three-stage architecture that separates behavioral analysis, technical scoring, and cheating detection for more accurate and reliable assessments.

## Base URL

```
/api/response/v2.5
```

## Key Features

- ✅ **Independent Configuration** - No dependency on V2 or earlier versions
- ✅ **Multi-Stage Processing** - Separate behavioral, technical, and cheating analysis stages
- ✅ **Media-Aware Ratings** - Communication/confidence ratings from actual audio/video
- ✅ **Time-Based Analysis** - Relevance breakdown with timestamps from media
- ✅ **Enhanced Base Answer Comparison** - Multi-dimensional scoring for subjective questions
- ✅ **Better Accuracy** - Each stage analyzes what it can actually observe

## Endpoints

### 1. Analyze Media Response (Video/Audio)

```http
POST /api/response/v2.5/analyzeMediaResponse
```

Analyzes video or audio responses using V2.5 multi-stage processing.

#### Request Body

```json
{
  "experience": "3",
  "jobRole": "Full Stack Developer",
  "question": "Explain the differences between REST and GraphQL",
  "candidateScreeningId": "screening_123",
  "jobApplicationId": "app_456",
  "questionId": "q_789",
  "answerFileId": "file_abc",
  "skillName": "System Design",
  "type": "video",
  "maxTime": 300,
  "file_uri": "https://example.com/video.webm",
  "mimetype": "video/webm"
}
```

#### Parameters

| Parameter              | Type   | Required | Description                             |
| ---------------------- | ------ | -------- | --------------------------------------- |
| `experience`           | string | Yes      | Candidate experience in years           |
| `jobRole`              | string | Yes      | Target job role                         |
| `question`             | string | Yes      | Question asked to candidate             |
| `candidateScreeningId` | string | Yes      | Screening identifier                    |

| `file_uri`             | string | No       | Remote file URI (alternative to upload) |
| `mimetype`             | string | No       | MIME type when using file_uri           |

## Multi-Stage Processing Pipeline

### Video/Audio Processing

```
Input: Media file + metadata
    ↓
Stage 1: Behavioral Analysis (with actual media)
    ├── Transcription generation
    ├── Communication rating (from audio/video)
    ├── Confidence level (from vocal tone/body language)
    ├── Relevance breakdown (time-based from media)
    └── Behavioral pattern detection
    ↓
Stage 2: Technical Scoring (with transcription text)
    ├── Technical correctness assessment
    ├── Depth evaluation
    ├── Relevance analysis
    └── Answer quality scoring
    ↓
Stage 3: Cheating Detection (algorithmic)
    ├── Behavioral analysis
    ├── Pattern detection
    └── Confidence scoring
    ↓
Output: Complete merged analysis
```

### Subjective Processing

```
Input: Text answer + typing data
    ↓
Stage 1: Typing Analysis (algorithmic)
    ├── Paste detection
    ├── Focus analysis
    └── Behavioral patterns
    ↓
Stage 2: Technical Scoring (with text)
    ├── Technical assessment
    ├── Base answer comparison
    ├── Communication rating (from text quality)
    └── Confidence level (from answer quality)
    ↓
Stage 3: Cheating Detection (algorithmic)
    ├── Typing pattern analysis
    └── Behavioral indicators
    ↓
Output: Complete merged analysis
```

## Key Improvements Over V2

| Feature                  | V2                  | V2.5                          |
| ------------------------ | ------------------- | ----------------------------- |
| **Configuration**        | Shares V2_CONFIG    | Independent V2_5_CONFIG       |
| **Communication Rating** | Guessed from text   | From actual audio/video       |
| **Confidence Level**     | Estimated from text | From vocal tone/body language |
| **Relevance Breakdown**  | Generic             | Time-based with timestamps    |
| **Stage Separation**     | Mixed               | Clear separation              |
| **Modularity**           | Coupled             | Independent                   |

## Error Handling

All endpoints return errors in the following format:

```json
{
  "success": false,
  "version": "v2.5",
  "error": "Error message here",
  "stack": "Stack trace (development only)"
}
```

### Common Error Codes

| Code | Description                                 |
| ---- | ------------------------------------------- |
| 400  | Bad Request - Missing or invalid parameters |
| 404  | Not Found - Resource not found              |
| 500  | Internal Server Error - Processing failed   |

## Environment Variables

V2.5 respects the following environment variables:

- `NODE_ENV` - Environment mode (`development`, `staging`, `production`)
- `PORT` - Service port (default: 5000)
- `KAFKA_BROKER` - Kafka broker addresses
- MongoDB connection settings (inherited from service)

## Migration Guide

### From V2 to V2.5

1. **Update endpoint URLs**: Change `/v2` to `/v2.5`
2. **Review response format**: V2.5 includes additional metadata
3. **Check field sources**: Some fields moved from Stage 2 to Stage 1
4. **Test thoroughly**: V2.5 uses different processing pipeline

### Backward Compatibility

V2.5 maintains backward compatibility with V2 request formats. However, response structures may contain additional fields.
