# V2.5 Multi-Stage Response Processor

## Overview

V2.5 is a **completely independent** multi-stage response processing system that is separate from V2. It has its own configuration, lifecycle, and processing pipeline.

## Key Features

### 🔒 Complete Independence
- **No dependency on V2 configuration** - V2.5 has its own `V2_5_CONFIG`
- **Separate lifecycle management** - Independent initialization and state
- **Own environment handling** - V2.5-specific environment configurations
- **Dedicated logging** - Clear V2.5 namespaced logs

### 🎯 Multi-Stage Architecture

V2.5 implements a three-stage processing pipeline:

```
Stage 1: Behavioral Analysis (Video/Audio only)
├── Transcription
├── Communication assessment
├── Behavioral pattern detection
├── Language detection
└── Communication/Confidence ratings (from actual media)

Stage 2: Technical Scoring (All types)
├── Content analysis (from transcription for media types)
├── Technical depth assessment
├── Relevance evaluation
├── Answer quality scoring
└── Improvement suggestions

Stage 3: Cheating Detection (Algorithmic)
├── Behavioral analysis
├── Pattern detection
├── Contextual evaluation
└── Flag processing
```

## Usage

### Initialization

```javascript
const v2_5Processor = require("./response.processor.v2.5");

// Initialize with dependencies
v2_5Processor.initializeV2_5Processor({
  logger,
  client,
  models: {
    CandidateAnswerAiResponse,
    CandidateScreeningResult,
  },
  typingAnalyzer: analyzeSubjectiveTypingPatterns,
  // Optional: customConfig to override defaults
});
```

### Processing a Response

```javascript
const result = await v2_5Processor.processTypeWiseResponse({
  type: "video", // or "audio", "subjective"
  candidateScreeningId: "...",
  questionId: "...",
  // ... other response data
});
```

### Getting Configuration

```javascript
// Get current config
const config = v2_5Processor.getConfig();

// Get environment-specific config (without initialization)
const envConfig = v2_5Processor.getV2_5EnvironmentConfig();

// Check initialization status
const initialized = v2_5Processor.isInitialized();
```

## Architecture Benefits

### 1. **Separation of Concerns**
- V2 handles legacy processing
- V2.5 handles new multi-stage processing
- No interference between systems

### 2. **Independent Evolution**
- V2.5 can be updated without affecting V2
- New features can be added to V2.5 independently
- Different configuration strategies

### 3. **Clearer Responsibilities**
- Stage 1: Behavioral (requires media)
- Stage 2: Technical (requires transcription/text)
- Stage 3: Algorithmic (uses results from 1 & 2)

### 4. **Better Accuracy**
- Media-dependent fields assessed in Stage 1 (with actual media)
- Content analysis in Stage 2 (with transcribed text)
- No guesswork on fields that require specific data

## Stage-Specific Data Flow

### Video/Audio Types
```
Input: Media file + metadata
  ↓
Stage 1: Behavioral Analysis (with media)
  → transcription
  → communicationRating (from audio/video)
  → confidenceLevel (from audio/video)
  → relevanceBreakdown (time-based from media)
  → behavioral patterns
  ↓
Stage 2: Technical Scoring (with transcription)
  → correctPercentage
  → technicalDepth
  → responseCoherence
  → relevanceAssessment
  ↓
Stage 3: Cheating Detection (algorithmic)
  → isCheatingDetected
  → cheatingConfidence
  → cheatingIndicators
  ↓
Merge: Complete analysis
```

### Subjective Type
```
Input: Text answer + typing data
  ↓
Stage 1: Typing Analysis (algorithmic)
  → typing patterns
  → behavioral indicators
  ↓
Stage 2: Technical Scoring (with text)
  → All scoring fields
  → communicationRating (from text quality)
  → confidenceLevel (from answer quality)
  ↓
Stage 3: Cheating Detection (algorithmic)
  → isCheatingDetected
  → cheatingConfidence
  ↓
Merge: Complete analysis
```

## Migration Notes

To migrate from V2 to V2.5:

1. **For new features**: Use V2.5 by default
2. **For existing code**: V2 continues to work unchanged
3. **Configuration**: V2.5 has its own config - no V2 dependency
4. **Endpoints**: Same interface, just call `processTypeWiseResponse`
